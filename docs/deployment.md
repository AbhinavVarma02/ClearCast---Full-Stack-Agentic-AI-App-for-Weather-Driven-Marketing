# ClearCast Deployment

## Hosted: Hugging Face Space (Docker SDK)

ClearCast runs as a single Docker container on the existing Space
`abhinavvathadi/ClearCast-AI` (https://huggingface.co/spaces/abhinavvathadi/ClearCast-AI).
The README front matter selects `sdk: docker` and `app_port: 7860`.

```text
Container (user 1000)
  deploy/launcher.py  ── starts, health-checks, restarts, and stops:
    1. FastAPI orchestrator   python -m api.main         127.0.0.1:8001
         └─ MCP weather server subprocess (stdio)
    2. Fastify gateway        node gateway/dist/index.js 127.0.0.1:8787
    3. Gradio UI              python -m frontend.app     0.0.0.0:7860  ← only public port
```

* **Build**: multi-stage `Dockerfile`. Stage 1 builds the gateway with
  `npm ci` (locked by `gateway/package-lock.json`) and prunes dev dependencies.
  Stage 2 is `python:3.13-slim-bookworm` with the Node 22 binary copied in, the
  locked Python dependencies (`requirements.txt`, generated by
  `uv pip compile --universal`), and only the runtime packages.
* **Secrets** (Space settings → Variables and secrets): `OPENAI_API_KEY`,
  `OPENWEATHERMAP_API_KEY`; optional `LANGCHAIN_API_KEY` (tracing is enabled
  only if `LANGCHAIN_TRACING_V2=true` is also set). The launcher passes provider
  secrets only to the orchestrator. The gateway and UI receive per-boot random
  tokens instead.
* **Startup**: the orchestrator answers health checks immediately and discovers
  MCP tools in the background (no OpenAI or OpenWeatherMap calls at startup).
  The UI header shows readiness from `GET /ready` on the gateway. Missing secrets
  are reported by name in readiness and as a `configuration_missing` error.
* **Failures**: a crashed child is restarted with exponential backoff (at most 3
  restarts in 10 minutes). After that, the launcher exits so the Space shows a
  runtime error instead of serving a half-working app. SIGTERM stops children in
  reverse order.

### Deploy

```bash
git push space <branch>:main      # remote: https://huggingface.co/spaces/abhinavvathadi/ClearCast-AI
```

### Verify

```bash
python scripts/smoke_test.py --url https://abhinavvathadi-clearcast-ai.hf.space --expect-live
```

The smoke test drives the public Gradio API like two browser sessions. It
generates a coffee-shop plan and an outdoor-fitness plan, checks structure,
validation status, evidence consistency, session isolation, and credential
leakage, then approves and exports one plan. With `--expect-live` it makes real
provider calls (a few GPT-4o-mini requests and OpenWeatherMap calls).

### Roll back

The pre-upgrade Gradio-SDK revision is `bd0f16d`. To restore its exact file
tree as a new commit (no force push, history preserved):

```bash
git fetch space
ROLLBACK=$(git commit-tree "bd0f16d^{tree}" -p space/main -m "Restore pre-upgrade Space revision bd0f16d")
git push space "$ROLLBACK:main"
```

## Local

* `python app.py`: full stack with real providers (needs `.env`, Node.js 22+,
  and a built gateway).
* `docker compose up --build`: the same image as the Space; only port 7860 is
  published.
* Offline demo: see the README (synthetic weather plus a scripted model server).

## Not covered

* No durable storage: LangGraph checkpoints (`MemorySaver`) and review state
  live in memory and are lost when the container restarts or sleeps.
* One replica only: sessions are not shared across processes.
* No authentication beyond unguessable per-browser session IDs; the Space is
  public.
* Health and readiness are endpoints and logs, not monitored SLAs.
